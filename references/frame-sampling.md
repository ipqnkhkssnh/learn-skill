# 抽帧与投喂：采样策略、成本控制、base64 投喂

录屏 → 帧 → **JPEG → base64 → 多模态大模型** → 理解。这份文档管好中间那一步。

---

## 1. 采样密度决策表

| 录屏时长 | 建议 `--interval` | 预期帧数 | 备注 |
|---|---|---|---|
| < 30s | 0.25 – 0.5 | 60–120 | 动作密集，宁可多留 |
| 30s – 2min | 0.5 – 1 | 60–150 | 默认区间 |
| 2 – 10min | 1 – 2 | 120–300 | 配合去重，实际更少 |
| 10 – 30min | 3 – 5 | 100–300 | 只看关键节点，长等待段会自然被去重 |
| > 30min | 分段学 | 每段 ≤ 200 | 不要一次性学完，按"任务"切段 |

**目标区间：单遍 60–300 张、实际保留 40–150 张。** 少于 40 张通常漏信息，多于 200 张模型注意力会散、成本也顶不住。

```bash
# 典型调用
bash scripts/extract_frames.sh "$VIDEO" "$OUT" --interval 1 --max 300 --width 1280
```

### `--max` 的两层含义

1. **成本闸门**：先想清楚"我打算给模型看多少张图"。
2. **自动放大间隔**：当 `时长 / interval > max` 时，工具会**自动放大间隔以覆盖全程**，而不是砍掉尾部，并在 `manifest.json` 里标 `intervalAdjusted: true`。所以录屏很长时不用担心"只学了前 5 分钟"。

---

## 2. 去重阈值怎么调

工具对每帧算一个 **32×32 RGB 签名**，与上一张保留帧比较"整幅画面平均每颜色分量的变化量"（`manifest.json` 里每帧的 `diff` 字段），`diff > --threshold` 才保留。

| 场景 | 建议阈值 | 说明 |
|---|---|---|
| 默认 | `2.0` | 能抓住按钮/字段/弹窗/状态色变化，忽略编码噪声 |
| 界面变化很细微（只改一个状态色、勾选框） | `1.0` – `1.5` | 保留更多 |
| 视频有大量动画/水印/时钟在动 | `4` – `8` | 否则帧数爆炸 |
| 想检查"到底漏了什么" | `-1` | 保留每一张采样帧（调试用） |

调参方法：先在 `manifest.json` 里看 `diff` 分布——真正有意义的操作节点一般 `diff > 5`，如果看到大量 `2~3` 的帧被保留（多是动画/压缩噪声），就把阈值往上调；如果关键操作帧漏了，往下调。

`--min-gap 30` 表示"即使画面不变，也至少每 30 秒留一张"，用于长等待段保住时间锚点。不需要就设 `0`。

## 3. 关键片段二次加密

整体抽完发现某段看不清（字太小、动作太快、表单滚动），就对那一段单独再抽一遍：

```bash
# 00:62–00:78 这段表单填写，用 0.25s 间隔重抽到另一个目录
bash scripts/extract_frames.sh "$VIDEO" "$OUT-zoom" --start 62 --end 78 --interval 0.25 --width 1600
```

再看 `$OUT-zoom/frames/`。注意两遍的帧号是独立的，笔记里要写清来源目录。

## 4. OCR：可选，默认关闭

`--ocr on` 会用 macOS Vision 逐帧识别文字，写进 `manifest.json` 的 `ocr` 字段，并在 `index.md` 里生成"帧 → 文字"的对照表。

> **平台限制**：OCR 只有 **macOS 的 swift 后端**提供。Linux / Windows 上：
> `extract_frames.sh` 走 ffmpeg 或 OpenCV 后端时会打印"已按 --ocr off 继续"，
> `extract_frames.ps1` 同样只提示不执行（不会报错，也不会静默丢弃）。
> 这些平台上要做逐字识别，抽完帧后单独跑外部 OCR：
> `tesseract frames/frame_00001.jpg stdout -l chi_sim+eng`（或 paddleocr），再把结果与图片交叉验证。

**OCR 不是必需的。** 默认 `--ocr off`，主链路（JPEG → base64 → 多模态模型看图）完全不依赖它；ffmpeg / OpenCV 后端也没有 OCR。它补的是"看图"这条路的两个短板：**分辨率**（小字被缩放后糊掉）和**逐字精确**（模型可能把形近字读错）。

### 4.1 不开 OCR 会遇到什么

| 风险 | 具体表现 | 后果 |
|---|---|---|
| **小字看不清** | 模型读图有分辨率上限，运行时往往还会再缩放一次（如 1280×720 预览成 1066×600）；ERP 表格、密集字段容易糊 | 关键信息读不出 → 标成 `unclear` → 反而要二次抽帧放大，更费事 |
| **形近字读错** | 订单号的 `0/O`、`1/l/I`、`8/B`，金额、日期、编号 | **最危险**：技能里写下错误的字段名/按钮文案 → 下次按语义定位找不到元素 |
| **无法逐字断言** | 成功判据需要"状态列 == 待发货"这类精确值 | 只能凭印象，做不了严格校验 |
| **无法做文字 diff** | 相邻帧的变化只能靠肉眼比对 | 滚动、局部刷新、静默变化容易漏 |

### 4.2 不开 OCR 时的替代手段（常常比 OCR 更可靠）

1. **提高分辨率**：文字密集的界面用 `--width 1600`；注意运行时可能仍会缩放，抽完确认一次实际可读性。
2. **二次加密放大**：对关键片段 `--start/--end --interval 0.25 --width 1600`，等价于局部放大。
3. **真机实测取文案（最优）**：Playwright 的可访问性树/DOM 文本、a2desk 截图 + 实际操作确认——**活系统上的文字永远比录屏里的可靠**。模式 B 补学时优先走这条。
4. **直接问用户**：关键字段名/按钮文案拿不准就问，比猜便宜得多。
5. **标注来源**：凡写进技能当作事实的文字，注明来源。可信度排序：**真机实测 > OCR > 看图**。

### 4.3 什么时候开

- **必须开**：运行时/模型**没有看图能力**，只能靠文字理解画面（此时 OCR 是唯一文字来源；但仍建议同时用 base64 交给有视觉能力的模型交叉验证）。
- **建议开**：界面以**密集文本**为主（财务报表、日志、长表格），需要精确抄录；或要做逐字断言。
- **值得开**：表格/表单字段名太小、看图看不清；需要记录报错原文、单号格式。

**什么时候别开：** 录屏以图形操作为主、无关键文字；或帧数很多而看图已读得很清楚（OCR 会增加耗时与上下文长度）。

> OCR 是辅助，不是替代。**OCR 读错字比读不到更危险**——凡是 OCR 文本将写进技能作为事实的，最好用图片再确认一次。

## 5. JPEG → base64：把帧投喂给多模态模型

这是标准投喂链路：**抽帧产出 JPEG → base64 编码 → 作为多模态消息的图片输入 → 模型理解页面内容。**

### 5.1 两条投喂路径

| 路径 | 做法 | 什么时候用 |
|---|---|---|
| **A. 运行时看图工具（首选）** | 直接对 `frames/frame_00001.jpg` 调用运行时的看图工具（如 `read_image`） | 运行时自带看图能力——它内部就是"读 JPEG → base64 → 送模型"，不用你操心 |
| **B. 显式 base64 批次** | `python3 scripts/frames_to_base64.py "$OUT" --batch-size 20` | 需要换模型/换 provider 喂图、脚本化调用、或运行时**没有**看图能力 |

```bash
# 路径 A：整条链路一步到位（抽帧 + 打包）
bash scripts/extract_frames.sh "$VIDEO" "$OUT" --interval 1 --max 300 --base64 --batch-size 20

# Windows（PowerShell，选项同名）
pwsh -File scripts/extract_frames.ps1 "$VIDEO" "$OUT" --interval 1 --max 300 --base64 --batch-size 20

# 路径 B：只打包（跨平台，纯 Python）
python3 scripts/frames_to_base64.py "$OUT" --batch-size 20
```

### 5.2 批次产物长什么样

```
$OUT/batches/
├── batch_0001.json   {"batch":1,"count":20,"images":[{"index":1,"tLabel":"00:00.0",
│                      "file":"frames/frame_00001.jpg","mime":"image/jpeg",
│                      "width":1280,"height":720,"bytes":41234,
│                      "estVisionTokens":1196,"base64":"/9j/4AAQ...","ocr":"..."}]}
├── batch_0001.txt    仅 --data-uri 时产出：每行一个 data:image/jpeg;base64,...
├── index.json        各批次覆盖帧号区间、字节数、token 粗估
└── README.md         给人看的批次说明
```

投喂方式：把 `images[].base64` 作为图片内容（`data:image/jpeg;base64,<...>`）随同一条多模态消息发给模型；同一批的 `index`/`tLabel`/`ocr` 作为文字上下文一并给出。

### 5.3 批大小与顺序纪律

- **每批 20 张（默认）**，最多不超过 40 张。批太大模型会丢失细节、还容易超时。
- **必须按批次顺序、按 `index` 顺序理解**，并且**每批看完先写时间轴笔记**再读下一批。一次性吞 200 张的"总结式理解"会丢掉因果顺序，学到的东西会变成模糊印象。
- 单批同时受 `--batch-size` 和 `--max-batch-mb 6` 约束，避免请求体过大被截断。

## 6. 成本速查（视觉 token 粗估）

按 (宽/28)×(高/28) 估算（不同厂商差异可达 2 倍，只用于量级判断）：

| 输出宽度 | 16:9 单图 token | 100 张 | 200 张 |
|---|---|---|---|
| 1600 | ~1.9k | ~190k | ~380k |
| **1280（默认）** | **~1.2k** | **~120k** | **~240k** |
| 1024 | ~0.75k | ~75k | ~150k |
| 768 | ~0.43k | ~43k | ~86k |

**降成本的三根旋钮**（按优先级）：

1. **减帧数**：调大 `--interval` 或 `--threshold`，比降分辨率更有效，而且不牺牲可读性。
2. **降宽度**：1280 → 1024 省 ~35%；界面文字大、窗口不复杂时可以降到 1024。
3. **分段学**：只学当前任务相关的那一段，而不是整段录屏。

反过来，**小字密集的界面（ERP 表格、财务凭证）优先提宽度到 1600 + 开 OCR**，因为看不清导致的返工成本远高于 token 成本。

## 7. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 第一帧是黑屏/桌面 | 录屏开头有 1–2 秒启动 | 用 `--start 2` 跳过 |
| 帧数远少于预期 | 录屏者在同一页面停留很久 | 正常（去重的目的）；用 `--min-gap` 保留时间锚点 |
| 帧数爆炸（几百张） | 页面有动画/时钟/光标闪烁 | 调大 `--threshold` 到 4–8 |
| 鼠标看起来没动但界面变了 | 键盘快捷键 / 回车 / 自动刷新 | 看 `index.md` 相邻帧的文字差异 + 开 OCR |
| 滚动没被识别为"新页面" | 滚动只改变局部 | 已去重的帧里滚动是被合并的；需要细节就对那段二次加密 |
| 远程桌面/虚拟机画面偏糊 | VNC/SPICE 压缩 | 抽帧宽度别超过实际显示分辨率；必要时在 VM 内直接截图（走 a2desk 的 screenshot）作为补充证据 |
| 视频读不出时长 | 文件损坏 / 不是视频 / 特殊编码 | 先用播放器确认能播；或先转码再抽 |

## 8. 一次完整学习的命令序列（模板）

```bash
SKILL_DIR="${LEARN_SKILL_DIR:-$HOME/.agent/skills/learn-skill}"
VIDEO="/path/to/recording.mov"
OUT="$HOME/.agent/skills/.learn-cache/$(date +%Y%m%d-%H%M%S)-$(basename "${VIDEO%.*}")"

# 1) 抽帧 + 打包 base64
bash "$SKILL_DIR/scripts/extract_frames.sh" "$VIDEO" "$OUT" \
     --interval 1 --max 300 --width 1280 --ocr on --base64 --batch-size 20

# 2) 看索引，确认覆盖情况
sed -n '1,40p' "$OUT/index.md"

# 3) 逐批看图（用运行时的看图能力读 $OUT/frames/*.jpg，或按 $OUT/batches 投喂）
#    每批读完写时间轴笔记

# 4) 对看不清的片段二次加密
bash "$SKILL_DIR/scripts/extract_frames.sh" "$VIDEO" "$OUT-zoom" --start 62 --end 78 --interval 0.25 --width 1600

# 5) 归纳 → 落成技能包
bash "$SKILL_DIR/scripts/init_skill.sh" erp-order-management --system "ERP" --title "ERP 订单管理"
bash "$SKILL_DIR/scripts/validate_skill.sh" "$HOME/.agent/skills/erp-order-management"
```
