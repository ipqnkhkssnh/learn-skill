# 从帧到技能：理解与泛化手册

这份文档回答学习技能最核心的问题：**看完一堆截图之后，到底要产出什么、怎么保证产出的是"能力"而不是"死记的路径"。**

---

## 0. 先想清楚要产出什么：三层模型

```
L1 系统层  这是什么系统？入口在哪？怎么登录？谁有权限？导航骨架长什么样？
L2 页面层  每个页面做什么？有哪些区域/字段/按钮/列？能做什么操作？有什么反馈？
L3 任务层  为了达成某个目的，按什么顺序、用什么参数、看到什么才算成功？
```

录屏只展示了 **L3 的一条具体路径**。技能的价值在于把它还原成 **L1 + L2 + 参数化的 L3**。

一句话判据：**如果用户换一个订单号、换一个查询条件、甚至换一个功能（提交订单），这个技能还能不能用？** 不能，就说明还没泛化。

---

## 1. 看帧的正确姿势

### 1.1 读帧节奏

- 用抽帧工具产出的 `index.md` 做索引，`manifest.json` 拿时间戳。
- 每批 20–40 张，**严格按 index 顺序**读（视觉能力一次读太多会丢细节）。
- **读完一批先写笔记，再读下一批**。笔记是后面归纳的原料，不要靠脑子记。

### 1.2 每帧问自己 6 个问题

| # | 问题 | 为什么要问 |
|---|---|---|
| 1 | 这是哪个页面 / 哪个区域？ | 建立页面地图 |
| 2 | 页面标题、面包屑、URL、高亮菜单是什么？ | 定位与到达路径（语义定位优于坐标） |
| 3 | 鼠标在哪、点了什么？ | 触发动作 |
| 4 | 输入框里是什么值、什么格式？ | 参数与格式约束 |
| 5 | 这一帧相对上一帧**变化**了什么？（跳转/弹窗/表格刷新/提示条/列表变短） | 因果关系与预期反馈 |
| 6 | 出现了哪些新元素？消失了哪些？ | 状态机与条件渲染 |

### 1.3 三种标记，一个都不能少

笔记里每条都要标：

- `observed` —— 我**看到**的（"列表标题是订单管理，列有订单号/客户/金额/状态/操作"）
- `inferred` —— 我**推断**的（"回车应该也能触发查询"）
- `unclear @ 00:31` —— 我**没看清**的（字太小、动作太快）

`unclear` 不是失败，是**下一步动作**：用抽帧工具对那一段二次加密（`--start 31 --end 35 --interval 0.25`），或开 `--ocr on` 把文字抠出来。

### 1.4 特殊动作的识别技巧

| 动作 | 在静帧里怎么看出来 |
|---|---|
| 鼠标滚轮 | 内容整体上移、页面右滚动条位置变化、同一页面出现不同区块 |
| 拖拽 | 中间帧有选中高亮/半透明拖影，起止位置元素顺序变化 |
| 键盘快捷键 | 鼠标没动但界面跳转/弹窗；输入框一次性出现整段文字 |
| 下拉选择 | 同一位置先出现展开列表，后续显示选中值 |
| 提交/保存 | 出现 toast、按钮变 loading、列表多一行、状态列变化 |
| 分页/排序 | 表格行内容整体替换、页码高亮变化、表头出现箭头 |

## 2. L1 系统层：入口与前置条件

### 2.1 先做"第一帧分析"

抽出的 **frame_00001** 是录屏开始那一刻的**现状**。把它当成一张"前置条件清单"来读：

| 观察 | 推断出的前置条件 |
|---|---|
| 已经是某个业务页面，左侧菜单高亮 | 用户**已经登录**、已经进到该模块 → 登录与进入动作不在录屏里，必须标为"录屏外前置" |
| 浏览器有多个标签页、地址栏有内网 IP | 系统是 Web、内网访问、可能需要 VPN |
| 是桌面客户端窗口（有原生标题栏/菜单栏） | 入口是客户端程序，不是 URL |
| 右下角有企业 IM / 远程桌面窗口 | 可能通过跳板机/远程桌面进入 |

**这一步最容易犯的错**：把第一帧的状态当成理所当然，于是技能里只写"进入订单管理页 → 查询"，而用户下次真要用时卡在"ERP 从哪进、怎么登录"。**必须显式写出"录屏外前置"小节。**

### 2.2 前置条件四查

| 类别 | 要问的问题 | 写进技能的形式 |
|---|---|---|
| **身份 / 权限** | 需要什么角色？菜单/按钮是否因权限而隐藏？ | "需具备订单查看权限；无权限时左侧菜单不显示订单管理" |
| **环境** | URL / IP / 客户端版本 / 浏览器 / 是否需 VPN / 生产还是测试 | "入口 ${ERP_URL}；内网访问，需先连 VPN" |
| **数据** | 要操作的对象必须已存在且处于什么状态？ | "订单需处于「待发货」状态，否则「发货」按钮为禁用态" |
| **时序** | 必须先完成什么？ | "必须先完成对账，才能提交结算单" |

### 2.3 入口的推断素材

录屏里出现的任何一条线索都要收集：

- 浏览器地址栏 / 书签栏 / 历史下拉
- 桌面图标名称、开始菜单项、快捷方式
- 企业门户/工作台的入口卡片
- 登录页的域名与 SSO 跳转
- 客户端"关于/设置"里的服务地址

收集不到就**如实写 unknown**，并在汇报里请用户补充。**不要编一个像样的 URL。**

### 2.4 凭据怎么写

只写**来源**，不写**值**：

- ✅ "账号由用户提供" / "凭据在密码管理器中，条目名 `erp-prod`" / "环境变量 `ERP_USER` / `ERP_PASS`"
- ❌ "用户名 admin，密码 Admin@123"

## 3. L2 页面层：把屏幕拆成结构

一个页面文件要能回答"**这个页面是什么、有什么、能做什么、怎么到达**"。

### 3.1 结构拆解清单

| 维度 | 要提取的内容 |
|---|---|
| 到达路径 | 从哪个菜单/按钮/URL 进入；面包屑层级 |
| 用途 | 业务上解决什么问题（一句话） |
| 区域 | 顶部导航 / 筛选区 / 工具栏 / 列表区 / 详情区 / 弹窗 / 底部操作区 |
| 字段 | 名称、类型（文本/下拉/日期/数字）、是否必填（红星）、格式、校验提示 |
| 按钮 | 文案、主次（高亮/灰）、禁用条件、点击后的结果 |
| 表格 | 列名与顺序、排序、分页、行内操作、批量操作、全选 |
| 状态 | 加载中 / 空态 / 错误态 / 成功提示 / 二次确认弹窗 |
| 副作用 | 页面上的操作会不会改数据、发通知、产生下游单据 |

### 3.2 语义定位优先，坐标兜底

写"左侧菜单第二项"、"标题为「订单管理」的标签页"、"行尾的「详情」链接"，而不是"点击 (312, 480)"。

坐标只在**确实没有语义**时记（自绘界面、Canvas、游戏、远程桌面里的图片式界面），并且必须附上当时的**屏幕分辨率与窗口状态**，否则下次必然点错。

### 3.3 把"看到但没做"的东西变成资产

界面上出现的每个按钮/标签页都是**未来可能的任务入口**。即使这次没点，也要登记：

```
⚠️ 工具栏按钮「提交订单」：位于列表页右上角，主按钮样式。
   - 未点击，不知道点击后的表单/校验/确认流程
   - 推测：选中一行后提交，可能要求填写备注
   - 状态：needs-exploration（留给模式 B 补学）
```

这条记录就是**模式 B 的种子**：下次用户说"帮我提交订单"，直接在技能里找到入口，点进去边做边学。

## 4. L3 任务层：目的与配方

### 4.1 目的识别的四个反问

看到一段操作，依次问：

1. **他在干什么？**（表面动作：输入、点击、滚动）
2. **这一步的结果是什么？**（界面反馈：列表收敛、页面跳转、提示出现）
3. **为什么需要这一步？省掉会怎样？**（答不上来 → 说明没看懂，回帧重看或标 unclear）
4. **他真正想达成什么？**（任务目的：不是"点详情"，而是"确认这笔订单的状态和收货信息"）

写不出目的的步骤，不要写进技能——那是抄动作，不是学能力。

### 4.2 任务配方的骨架

```
目的 → 前置条件 → 参数 → 步骤（操作 | 输入 | 预期反馈 | 失败怎么办）→ 成功判据 → 副作用 → 异常分支
```

两个质量要点：

- **预期反馈必须可观察**：不是"查询成功"，而是"列表只剩 1 行，且订单号列等于 ${order_no}"。
- **参数必须有来源**：每个 `${param}` 说明它从哪来（用户提供 / 上游查询 / 系统生成）。

### 4.3 副作用与幂等

录屏里看不到副作用（因为录屏者往往只做一次），但要在技能里显式写：

- 会不会改变业务状态（订单状态、库存、余额）
- 会不会对外发送（短信、邮件、推送、对接第三方）
- 重复执行会怎样（是否幂等、会不会生成两条单据）

不知道就写 `unknown` 并在执行时**先确认**。

## 5. 泛化七式

| # | 从（录屏里的具体） | 到（技能里的泛化） | 例子 |
|---|---|---|---|
| 1 | 具体值 | 参数 + 来源 + 格式 | `SO20240912-0087` → `${order_no}`（10 位数字+字母，用户提供或上游查询） |
| 2 | 单条记录 | 按条件集合 | "查这一个订单" → "按 订单号/客户/日期区间/状态 查询订单列表" |
| 3 | 一条路径 | 入口地图 | "侧边栏→订单管理" → 记录所有可见入口（菜单、工作台卡片、URL 直达、搜索结果跳转） |
| 4 | 一次点击 | 能力矩阵 | "点了详情" → 该页面全部能力：查看/新建/编辑/删除/导出/打印/审批，并标注哪些验证过 |
| 5 | 一次观察 | 可断言判据 | "看到状态是待发货" → "断言：详情页状态字段 == 待发货" |
| 6 | 未知 | 待补清单 | 见到没点的按钮 → `unknowns` + `needs-exploration` |
| 7 | 动作顺序 | 前置条件图 | "先点 A 再点 B" → "B 的按钮在 A 完成前为禁用态" |

## 6. 完整示例：从 ERP 订单录屏到 `erp-order-management`

### 6.1 录屏事实（抽帧后看到的时间轴）

```
f001 00:00  已登录的 ERP 主界面，左侧菜单可见「订单管理」，顶栏有用户名
f004 00:04  点击「订单管理」→ 订单列表页（筛选区 + 列表 + 右上角「新建订单」「提交订单」按钮）
f007 00:07  在"订单号"输入框输入 10 位编码，点「查询」
f009 00:09  列表从 3 页收敛为 1 行
f012 00:12  点该行行尾「详情」→ 订单详情页
f015 00:15  详情页：状态=待发货、金额、收货人、商品明细表
f021 00:21  鼠标滚轮下滚 → 出现「物流信息」「操作日志」折叠区
f028 00:28  滚回顶部，录屏结束
```

### 6.2 ❌ 错误学法（抄路径）

```markdown
# ERP 查订单
1. 打开 ERP
2. 点订单管理
3. 在搜索框输入 SO20240912-0087
4. 点查询
5. 点详情
6. 往下滚看物流
```

问题：换订单号就废；不知道为什么这么做；ERP 从哪进没说；订单管理页还有什么不知道；提交订单完全没覆盖。

### 6.3 ✅ 正确学法（产出地图 + 能力）

`SKILL.md`（节选）：

```markdown
## 1. 系统入口与登录前置（录屏开始前就已成立）
| 项 | 内容 | 置信度 |
|---|---|---|
| 系统 | ERP（Web，内网） | observed |
| 入口 | unknown（录屏第一帧已登录，未见地址栏）——**需用户补充** | inferred |
| 登录 | 已登录状态；登录动作不在录屏内 | observed |
| 凭据来源 | 由用户提供 | — |
| 环境 | unknown（生产/测试未确认，写操作前必须确认） | unclear |

## 3. 能力清单
| 能力 | 状态 | 配方 |
|---|---|---|
| 按条件查询订单 | ✅ 录屏验证 | tasks/query-orders.md |
| 查看订单详情 | ✅ 录屏验证 | tasks/view-order-detail.md |
| 新建订单 | ⚠️ 仅见按钮 | — |
| 提交订单 | ⚠️ 仅见按钮，未点击 | —（needs-exploration） |
| 导出/打印 | ⚠️ 仅见入口图标 | — |
```

`pages/order-list.md`（节选）：

```markdown
# 页面：订单列表
- 到达路径：左侧菜单「订单管理」
- 区域：顶部筛选区 / 工具栏 / 列表区 / 分页
- 筛选字段：订单号(文本)、客户(文本)、下单日期(日期区间)、状态(下拉)
- 列表列：订单号 | 客户 | 金额 | 状态 | 下单时间 | 操作
- 行操作：详情（链接）
- 工具栏按钮：新建订单、提交订单、导出
- 反馈：查询后列表刷新，无结果时显示"暂无数据"
- 证据：f004–f009
```

`tasks/query-orders.md`（节选）：

```markdown
# 任务：按条件查询订单
目的：在大量订单中定位到目标订单
前置条件：已登录且具备订单查看权限；环境已确认
参数：${order_no}(可选) ${customer}(可选) ${date_from} ${date_to} ${status}(可选)
步骤：
 1 左侧菜单点「订单管理」 → 出现订单列表页

成功判据：列表首行订单号 == ${order_no}
副作用：无（只读）
```

### 6.4 后续："帮我提交订单" 怎么走模式 B

1. 读技能 → 发现「提交订单」只有入口记录、没有步骤 → 待补清单：按钮点击后的表单字段、校验规则、确认弹窗、成功后状态变化、是否需要权限。
2. 选通道（优先 `remote-a2desk`）→ 进入订单列表页 → **先截图确认前置状态**。
3. 选中目标订单 → 点「提交订单」→ 截图 → 记录弹出的确认框文案与按钮。
4. 按表单填入用户给的参数 → 提交前**再确认一次**（写操作）→ 提交 → 截图记录成功提示与订单状态变化。
5. 回写：新增 `tasks/submit-order.md`、更新 `pages/order-list.md`（补充按钮行为与前置条件）、`SKILL.md` 能力清单把"提交订单"从 ⚠️ 改成 🟡/✅、`meta.json` 版本 0.1.0 → 0.2.0、从 `unknowns` 移除该项、`CHANGELOG.md` 追加一条带证据截图名。
6. 汇报："补学了提交订单（含校验规则 X/Y），仍未知审批流与批量提交。"

## 7. 落盘前自检 8 问

1. 换一个参数值，技能还能用吗？
2. 前置条件（尤其"录屏前就已成立"的那部分）写清楚了吗？
3. 每一步都能说出目的吗？
4. 每条描述都有帧号或实测证据吗？
5. 界面上看到但没操作的功能，进 `unknowns` 了吗？
6. 有没有写进任何凭据或真实客户数据？
7. 技能名是 kebab-case 吗？frontmatter 有 `name` + `description` 吗？
8. 一个从没看过录屏、也没用过这个系统的人，只看技能能上手吗？

第 8 问是最硬的判据。做不到，就回去把 `pages/` 和 `tasks/` 补厚。
